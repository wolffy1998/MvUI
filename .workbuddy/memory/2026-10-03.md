## 列表/图标对齐旧版 mamepgui 1.8.2

### 1. Description 列被挤成 0 宽（"描述没有正常显示"的真因）

`views.rs::draw_table` 原来给 Description 用
`Column::remainder().resizable(true).clip(true)`。
egui_extras 只在**最后一列**是 remainder 时才每帧重算宽度；非末列且
`resizable(true)` 的列，从第 2 帧起走
`Size::exact(prev_width)`（table.rs:620-645）——**宽度被第一帧的
leftover 永久冻结**。首帧 dock 布局尚未稳定、可用宽度很小，于是
Description 被压成 ~0 像素并被 `.clip(true)` 剪掉，整场会话都看不见。

修复：Description 改 `Column::remainder().at_least(160).resizable(false).clip(true)`
（非 resizable 的 remainder 每帧重算 = 永远吃满剩余宽度，与旧版
"描述列最宽"一致）。其余列改用显式初值 `Column::initial(w)`
（`COL_DEFAULT_WIDTH`，取自旧版 `res/mamepgui.ini` 的 `column_state`
解出的 242/100/36/142/67/33/58）+ `COL_MIN_WIDTH` 下限。
两个常量加在 `app.rs`（紧邻 `COLUMN_TITLES`）。

顺带说明：列重排用拖动**表头标签**（`dnd_drag_source`，id 以列号
为键所以重排后身份不丢），hover 到别的列时 `col_order.swap`，
与列宽的拖拽手柄不冲突。

## 追加：描述列居中错位 + 整行高亮 + 分类面板可停靠

用户反馈"描述列没显示描述、跑到右侧那列了；彩色方块在描述列里"。真因是
**`SelectableLabel` 会把文字在自己的 rect 里居中**（`selected_label.rs:64`
`align_size_within_rect`），而单元格用的是
`add_sized(ui.available_size(), …)`，于是描述文字被推到列中间，看起来像
落到了下一列，左边只剩一个状态方块。旧版根本不是这样：Qt
`GameListDelegate::paint`（gamelist.cpp:987）只在 `COL_DESC` 里画
icon + 文字，`rectText.left += decoSize + cloneOffset + 6`，文字紧贴图标
并左对齐。

改法（views.rs）：

- 新增 `cell_text(ui, text, color)` = `Label::new(...).truncate().selectable(false)`
  —— 左对齐。`selectable(false)` 必须加：egui 的
  `interaction.selectable_labels` 默认 true，否则每个单元格都会
  `Sense::click_and_drag()` 做文本选择，拖过列表会变成选字。
- 行内不再放 `SelectableLabel`，改成 `row.set_selected(is_sel)`——egui_extras
  会给每个 cell 画 `selection.bg_fill` 并把 rect 外扩半个 item spacing，
  所以**整行连成一条高亮带**（用户要的"整行变颜色"）。
- 文字颜色自己算：`visuals.selection.stroke.color` / `text_color()` /
  `weak_text_color()`，选中时切换到 selection 前景色。
- `TableBuilder::sense(Sense::click())` + `row.response()`（所有 cell 的
  response 并集）当整行命中目标。**注意**：`StripLayout::add` 是先跑
  `add_cell_contents` 再 `child_ui.response()`，即 cell 的 widget 注册在
  内容之后、位于最上层，会吃掉内部控件的点击 —— 所以表头排序点击改成取
  `header.col()` 返回的 **cell response**，标题用普通 `Label`。egui 的
  hit-test 对 click / drag 分开取最上层（hit_test.rs `hit_filter`），
  所以 `dnd_drag_source` 的 drag 仍正常。
- clone 缩进从 `format!("   {label}")` 改成 `ui.add_space(16.0)`（旧版
  `cloneOffset = 16`）。
- 不可用标记改用 `res/status-na.png`（旧版同款），新增 `icons::put()`
  把它画在状态方块右下 8x8 处（`ui.put` 不推进布局游标）。
- 表头标题也改左对齐（Qt QTreeView 默认左对齐）。

## 描述列宽度会被"历史最大内容宽度"冻结

`TableState::load` 对 **非 resizable 的 remainder** 列做
`.at_least(column.width_range.min.max(*max_used))`——`max_used` 是该列
历史最大内容宽度。窗口放大时描述列变宽、长描述把 `max_used` 顶到几百像素，
之后**缩小窗口描述列也不肯变窄**，把后面的列挤出右边缘。

修：`TableBuilder::id_salt(("gamelist_table", (avail_width/24).round()))`
—— 按可用宽度分桶，每个宽度各有一份列宽状态，remainder 每帧按当前宽度
重算。副作用：改变窗口宽度会丢失手动拖过的列宽（回到该桶的默认值）。

## 顺手修掉的老 bug：表头排序/列重排一直是死的

`views.rs::draw_table` 里
`let header_sort_requested = std::cell::Cell::new((usize::MAX,false));`
`let header_sort_requested_clone = header_sort_requested.clone();`

**`Cell<T: Copy>` 自己就是 `Copy`**，所以 `.clone()` 是值拷贝；而
`tb.header(20.0, move |mut header| …)` 是 `move` 闭包，等于把这份拷贝搬进
闭包 —— 里面 `hs_req.set(...)` 写的是副本，外面永远读到 `(usize::MAX,false)`。
`swap_req` / `swap_cell`（列重排）同理。**所以"点表头排序"和"拖列换序"
从实现那天起就没生效过。**

改：两处都换成 `std::rc::Rc<std::cell::Cell<..>>` + `Rc::clone`（共享同一份
Cell）。表格 body 里的 `clicked/launched/ctx_menu` 不用改 —— 那个闭包不是
`move`，按 `&Cell` 借用，写入是通的。

## 表头点不动：egui 的 hit-test 拿不到表头单元格

`Rc` 修完之后表头点排序**还是不动**。逐步排查（加 eprintln 打
`Response.rect/interact_rect/hovered/clicked`、`ui.clip_rect()`、
`ui.layer_id()`、`ctx.layer_id_at(ptr)`）：

- 表头单元格 rect/`interact_rect` 都正确、指针确实在 rect 里，
  但 `hovered=false clk=false`；换成单元格里的普通 `Label`（甚至
  `ui.interact` 直接覆盖整个 cell）也一样 —— 说明**不是** Cell 拷贝、
  不是 clip、不是 layer（`Order::allow_interaction()` 在 0.29 全部返回
  true）、也不是 `dnd_drag_source` 抢事件。
- 表格 body 里同样的写法却完全正常。所以是表头这一块特有的问题。

最后的做法：**表头交互不再依赖 egui 的命中测试，自己算**。
`tb.header(...)` 里把每个表头单元格的 `ui.max_rect()` 收进
`Rc<RefCell<Vec<(usize, Rect)>>>`；`tb.header(...)` 返回的 `Table` 先接住
（`let table = tb.header(...)`），在 `.body(...)` 之前手动做判定：

- 排序：`pointer.primary_clicked()` 且指针落在某个表头 rect 内 → 发排序请求
- 列重排：`primary_down()` 期间，按下点所在列 ≠ 当前指针所在列 → 交换两列
  的 slot；按下点优先用自己记的 `drag_from`，回退用 egui 的
  `pointer.press_origin()`
- **必须用 `latest_pos()` 而不是 `interact_pos()`**：按住按钮时 egui 的
  `interact_pos()` 返回的是**按下原点**，用它做拖拽判定会永远落在起始列，
  列永远换不了

验证到的：`[dbg]` 日志确认 press 命中列 0、指针移动时 `at` 依次变成 1、2；
截图确认点表头后表头变成 `Description ▲` 且列表重排、ini 里
`sort_column` 跟着变。**列拖拽换序只做到逻辑正确+按下命中的验证**，
合成鼠标（`SetCursorPos`/`mouse_event`）拖拽过程中按钮 DOWN 状态会被
系统那一侧清掉（`down` 有一帧变 false），所以没能端到端复现，需真人拖一次确认。

  6 个图片标签不再溢出）

## 列边界竖线 + 描述列可拖动（egui_extras 的列宽机制）

用户先问"Description 和 Name 之间为什么没有竖线"，接着问"描述宽度还是不能拖"。
两件事同一个根因，都在 egui_extras 0.29 的列宽逻辑里（`src/table.rs`）：

1. **竖线**：`header()` 末尾的收尾循环里，只对 `column.resizable.unwrap_or(resizable)
   == true` 的列画 `line_segment`（`table.rs:905-907`），颜色取空闲态的
   `widgets.noninteractive.bg_stroke` = 灰 190。线从 `table_top` 画到
   `ui.min_rect().bottom()`，所以是**贯穿表头+表体**的一条。描述列因为
   `resizable(false)` 被跳过 → 少了那条线（其余列都有，所以看着像 bug）。
2. **拖不动**：同一条规则，`resizable(false)` 就没有 `resize_column` 交互区。

关键发现（决策依据，记牢）：**`Sizing::to_lengths` 对 `Size::Absolute` 只返回
`initial`，完全忽略 range** ——
`Size::Absolute { initial, .. } => initial`（`sizing.rs`）。而
`TableState::load` 的刷新分支对**非 resizable 的 Absolute 列**每帧构造
`Size::exact(width)`。两者合起来 = 非 resizable 的 `Column::initial(w)`
**每帧都用我们的 w**，既不会像 `remainder` 那样被 `max_used_widths` 卡住下限，
也不会像 resizable 列那样冻结在第一帧。所以"自己算宽度 + resizable(false)"
是唯一能既可控又无副作用的方案。

最终实现（`views.rs::draw_table`）：

- 描述列 = `Column::initial(desc_w).resizable(false).clip(true)`；
  `desc_w = self.col_desc_width.unwrap_or(剩余宽度)`，`None` = 自动铺满。
- 新增 `MameApp.col_desc_width: Option<f32>`（ini `column_desc_width`，
  空 = 自动）。
- 拖拽自己实现：`desc_hdr` 记下描述列表头 cell 的 rect；指针进入
  `rect.right() + spacing/2` ±4pt 就 `ResizeColumn` 光标；按下时用
  egui temp data 里的锁存位保持整个手势，宽度直接由指针 x 反算
  `p.x - spacing/2 - rect.left()`，clamp 到 `[COL_MIN_WIDTH, 剩余宽度]`。
  双击该边界 → 回到自动（`col_desc_width = None`）。
- **加了一列零内容 spacer**（`Column::initial(剩余-描述宽).resizable(false)`）：
  egui_extras 只会把余量给 `remainder` 列，而两个 remainder 会平分余量，
  所以描述列一旦改成 Absolute，用户把它拖窄后右侧会留白。spacer 吸收差额，
  条纹/选中底色照样铺满（背景是按 cell rect 画的）。header 和每行都要多一个
  `col()`，否则条带会短一截。
- 表头点击/换列的命中测试要**排除列边界 ±4pt**（`col_at` 里加判断），
  否则点边界想拖宽度会顺带触发排序。
- `table_key` 之外再把**列顺序**混进 id_salt：egui_extras 的 `column_widths`
  是**按位置**存的，换列后不重建状态的话每列会继承"原来占这个位置的列"的宽度
  （实测 Mftr=88/ROMs=150 这种错位）。重建时用上一帧量到的、**按列 id 索引**的
  宽度重新播种，所以换列不丢宽度、窗口变化也不丢。
- 每帧把 `hdr_rects` 里的 cell 宽度按列 id 存回 `ui.data`
  （`gamelist_col_widths`），作为下次重建的 initial。

验证：拖拽后 ini 写出 `column_desc_width=245`，截图实测列宽 ≈248（有 ~3pt
是"表格左边界估算"的系统偏差，不是 bug）；条纹行从最后一列一直铺到节点边界
（x=1386 还是 (248,248,248)，1388 才是节点灰线）→ **没有空档**。
受控实验（ini 写 `column_desc_width=400`）时程序把值改成 370 = 当前 leftover

## 按 mamegui-rs/README.md 的审计清单修完 P1/P2/P3（用户指定）

**关键事实（下次别猜）**
- 图标嵌入的真因：build 脚本 cwd 是 **package 根**（`crates/mamegui-app`），
  相对路径 `assets/icons` 恒为空 → 图标表一直是空的，界面全走程序化方块。
  正解 `CARGO_MANIFEST_DIR/../../assets/icons`。**验证方法**：`cargo build` 后看
  `target/*/build/mamegui-app-*/out/icon_assets.rs` 的行数（105 项才对）；
  或跑起来看树里的 `32x32/folder.png`。
  另：Windows `canonicalize()` 会带 `\\?\` 前缀，转正斜杠后是 `//?/C:/…`，
  写进 `include_bytes!` 虽能编，但要 `strip_prefix("//?/")` 更稳。
- source ini 名要按 **MAME 本体**（`mame-0.168/src/emu/emuopts.cpp::parse_standard_inis`）：
  `core_filename_extract_base(source_file, strip_extension=true)` = **只取文件名**
  （丢目录）并在**最后一个点**截断，路径是 `<inidir>/ini/source/<name>.ini`。
  旧版 mamepgui 的 `sourcefile.replace(".c",".ini")` 保留目录、且对 `.cpp` 会产出
  `pacman.inipp` —— 别照抄那部分。
- `ramoption` **总是**带文本节点（`<ramoption default="1">2</ramoption>`），
  所以只走 Start 事件；属性必须在 Start 分支读。
- 审计定级要用**回填之后的最终状态**；旧版是先算 `allinParent` 再"只降不升"，
  但因为旧版扫描阶段已把父集 rom 传播给克隆集，两者等价。
- fixdat 四模式的分流在 `audit.cpp::exportDat`（约 80-175 行）：
  `completelyMissing = missingCount >= 总rom - biosRom数 - nodump数 || completelyMissingClone`，
  再按 INCOMPLETE（丢 completelyMissing）/ MISSING（丢 !completelyMissing）过滤；
  元素名是 `<game>` 不是 `<machine>`。
- `sevenz-rust 0.6` 的 entry 是**字段**不是方法：`e.has_crc` / `e.crc`（`u64`）；
  `for_each_entries(|entry, reader|)` 给的 reader 可直接读解压内容 —— 用它做单遍扫描。
- 旧版 bool 启动参数就是 `if (currVal == "0") opt.prepend("no")`（gamelist.cpp:3547），
  所以"只认 0"是对的，清单里那条是误报。

## 左侧文件夹树按旧版参考布局重写（`ui.rs::draw_folders`）

用户给了旧版（Qt 1.8.2 / MAME Plus）的两张截图当参考，要求：
一级「有下级的画小下拉符号、没有的也要和下面那些对齐」，二级「和一级的文字处对齐」。

**改法**：不再用 `CollapsingState::show_header`（它给可展开行单独画 toggler，
叶子行没有，所以两者的图标/文字差了一个分支列的宽度），改成自己画行：
- `folder_row()`：一级行 = 分支列（宽度取 `spacing().indent`，与 egui toggler 同宽）
  + `folder.png` + `selectable_label`；**每行都分配分支列**，只有 `expandable` 时才在
  里面点响应并画三角，所以叶子行的图标/文字与可展开行落在同一网格。
- `paint_branch_arrow()`：自绘扁平灰三角（▶/▼），比 egui 自带的实心黑三角轻。
- `folder_child_row()`：二级 = 图标 + 文字，无分支列。
- `folder_body()`：临时改 `spacing().indent` 后 `ui.indent`，并把
  `visuals.indent_has_left_vline` 置 false（旧版树没有那条竖线）。
- **二级缩进量在运行时实测**：`folder_row` 返回
  `label.rect.min.x - row_left + spacing().button_padding.x`（父级文字起点），
  拿来当 body 的 indent。不要用 `分支+间距+图标+间距` 推算——实测值和推算值差好几个
  点，推算出来的二级图标会明显偏右。
- 去掉了可展开行的 `.strong()`：旧版所有行字重一致。

**坑**：`CollapsingState::toggle()` 只翻内存里的 flag，**不持久化**；旧代码是靠
`show_body_unindented` 顺带 `store` 的。我们不再走那条路，所以 toggle 后必须自己
`state.store(&ctx)`，而且开着的时候每帧再 store 一次（否则应用一空闲，动画收敛到
`open=false`，节点会自己合上）。

**参考图与旧版源码不一致处**：旧版 `gamelist.cpp:2830` 只给一级条目设 `folder.png`
（二级没有图标），但用户给的参考图里二级也有图标；按参考图做了。
参考图里 `我的收藏` 是金星图标，我们（和 1.8.2 源码）用 folder 图标 —— 未改，等用户决定。

**验证工具**（`.workbuddy/tools/`）：`shot_tree.py`（最大化/点击/滚轮/截图，
**按 exe 路径筛选窗口**——旧版 1.8.2 的进程也叫 `mamegui.exe`，只按进程名会抓错窗口，
之前就误抓过旧版界面）、`measure_rows.py`（逐行量出图标 x / 文字 x / 分支列 x）。
本轮实测：一级图标 x=78、文字 x=130；二级图标 x=134（父级文字 130，差 4px）。

### 修掉的四处行为偏差

1. **列拖拽重排至今是死的**（第二轮只修好了"起点记录"，落点没修）。
   `draw_table` 的表头指针处理是一条 `else if` 链里出现**两次 `else if down`**，
   第二个永不可达 → `header_drag` 恒为 `(from, from, false)` → `moved` 恒 false
   → `move_column` 是死代码，且松手被当普通点击**反而排了序**。
   修法：抽纯函数 `header_step(pressed, down, resize_active, drag_active, sep, slot)`
   → `HeaderStep` 枚举（Idle/BeginResize/BeginDrag/UpdateResize/UpdateDragTo/
   EndResize/EndDrag），列位移抽 `shift_slot()`（整段平移，非交换）。
   **教训**：一个手势 = 一个显式状态机，别用 `else if` 链 + 散落的 Option 状态；
   纯函数形态才能写测试。
2. **source 级 ini 保存到错误路径**：`windows.rs::apply_edit` 手拼
   `<mame>/source/<sourcefile.replace(".c","")>.ini`，与读取侧
   `OptionCore::ini_file_for`（`<inidir>/ini/source/<去扩展名文件名>.ini`）不一致
   → 改完下次读回来是空的；`pacman.cpp` 还会产出 `pacmanpp.ini`。
   修法：写入侧改调同一个 `ini_file_for`，BIOS/Cloneof/Game 三层一并统一，
   写失败进日志而非静默。
3. **GUI 设置污染 MAME 选项**：`load_ini` 的 GUI-overlap 按**名字**匹配，而
   `language` 既是 GUI 设置（zh_CN）又是 MAME 核心选项（English）→ 被覆盖后
   还会被写进 `mame.ini`。修法：只认 `guivisible="1"`（模板里恰好 14 个，
   与注释"14 GUI keys"吻合），符合设计文档 §6.4-4「GUI 层设置不进 ini 体系」。
4. **加锁顺序反了可能死锁**：`run_audit` 是 `lib → opts`，UI 的 `ensure_chain`
   是 `opts → lib`。修：审计线程先取 opts 读完路径释放，再取 lib。**全局统一
   `opts → lib`**（std Mutex 非重入，顺序必须一致）。
