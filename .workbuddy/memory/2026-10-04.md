### 行 hover 只有一小块的真因（重要，egui_extras 机制）

`egui_extras 0.29` 的行高亮靠 `TableBody::capture_hover_state`：它拿
**`row.response()`**（= 所有 cell 的 response 并集）的 `hovered()`，命中就把
`hovered_row_index` 写进 temp data，**下一帧**该行每个 cell 的
`StripLayoutFlags.hovered=true`，`layout.add` 再给每个 cell 画
`widgets.hovered.bg_fill`（rect 外扩半个 item spacing，所以连成一条带）。

而 `TableRow::col` 的 response 来自 `StripLayout::add` 末尾的
`child_ui.response()` —— **cell 内最后一个 widget 的 response**。我们的 cell
最后加的是 `cell_text()` 的 `Label`，它的 rect 就是**文字包围盒**，于是
"行是否 hover"退化成"指针是否在文字上"。

**修法**：`ui.interact(cell_rect, id, Sense::click())` 必须放在
`row.col()` 闭包的**最后**（在 `match c {...}` 之后），让整格 rect 成为
cell 的 last response。顺带 `row.set_selected(is_sel)` 放在画 cell **之前**
（它对"之后添加的 cell"生效），选中底色即铺满整行。
→ 教训：egui_extras 里"每行 hover/选中"是**跨帧 + 依赖最后一个 widget** 的机制，
自己往 cell 里塞 widget 时必须清楚谁在抢 last response。

## 删掉「垂直页签」空开关（用户确认"完全可以删除"）

用户问它有什么用 → 查清后建议删，用户同意。

**它到底是什么**：`QMainWindow::DockOptions::VerticalTabs`（Qt 官方文档
0x10）——"两侧停靠区的标签栏竖排显示；不设则所有区域的标签都在底部。
Implies AllowTabbedDocks"。旧版 1.8.2 就是纯开关
（`mainwindow.cpp:1362-1365` `opts |= VerticalTabs` / `&= ~VerticalTabs`），
默认**开**（`:1171` 读 `value("vertical_tabs","1")`）。

**概念纠正（我一开始讲错过）**：`VerticalTabs` 只管标签栏**方向**，
`AllowTabbedDocks`（能否叠放成标签页切换）**默认就是开的**
（Qt 默认 `AnimatedDocks | AllowTabbedDocks`，旧版没重载 `dockOptions()`）。
"implies" 是"勾了会顺便打开叠放"，不是"不勾就不能叠放"。
egui_dock 本来就支持上下左右停靠 + 叠放 + 分组拖动，这个开关是纯装饰。

**我们这边本来就是空壳**：`app.rs` 字段名就叫 `vertical_tabs_stub`，
全工程仅 3 处引用（字段声明、`new()` 里 `false`、菜单 checkbox），
**没有任何地方读它**，也不写 ini。

删除范围（5 处，全工程 `grep -i vertical_tab` 现已零命中）：
- `app.rs` 字段 `pub vertical_tabs_stub: bool`
- `app.rs` `new()` 里的 `vertical_tabs_stub: false`
- `ui.rs` 视图菜单的 `let vt = self.tr("Vertical Tabs")` + `ui.checkbox(...)`
- `i18n.rs` 简中 `("Vertical Tabs","垂直页签")`、繁中 `("Vertical Tabs","垂直分頁")`
  （`i18n.rs` 的 `dynamic_keys_are_translated` 测试只校验动态 key
  = 列名/级别名/dock 名/文件夹名，删字面量条目安全）

验证：check 0 warning、test 22 通过、release 重建、截图确认菜单里该项已消失

### 真因一：`Order::Background` + `screen_rect()` 会被面板盖不住

原实现 `ctx.layer_painter(LayerId::new(Order::Background, ..))` + `screen_rect()`。
`Order::Background` 确实是最低层（`egui-0.29 layers.rs:34 Order::ALL` 第一项，
`Layers::drain` 按它遍历），但图片是**不透明**铺满整个 `screen_rect()`，实测把
**不透明**的菜单栏/工具栏（都用 `panel_fill`）一起埋掉。逐像素验证：同一坐标
(900,60) 全不透明时是背景图色 `(12,15,22)`，限缩背景时是面板色 `(27,27,27)`。
换成 `Order::PanelResizeLine` 无效 → 不是图层序问题。
**正解**：`draw_background(&mut ui)` 改成用 `ui.painter_at(ui.max_rect())` 在
**中央面板自己的 frame 里**画，绘制顺序交给 egui，图天然在所有 dock 之下。
（`p.image` 的 clip 来自 painter，所以 menu/toolbar 覆盖不到图。）

### 真因二：半透明槽位搞错了两次

- `extreme_bg_color` 半透明 → **没用**，那是 egui 的 void/回退色，不是 dock 底色，
  面板不变、图根本看不见。
- `window_fill` 半透明 → 槽位对了（`egui_dock-0.14 style.rs:704 from_egui` 就是从
  `window_fill` 推 `TabBodyStyle::bg_fill`，它给每个 dock leaf 上色），但因为图还
  铺满全窗，veil 一起把文字冲淡。
- 两者分开后才成立：图进 `CentralPanel`，`window_fill` 半透明 128
  （= 旧版 `setTransparentBg` 的 `QPalette::Base` → `rgba(0,0,0,128)`），
  `panel_fill`/`faint_bg_color` 跟着 veil，`override_text_color = None`。
  表头拖拽幽灵底色改用 `panel_fill`（浮层要实体底，用半透明会重影）。
- 中途我一度把 `window_fill` 也改回不透明"修过头"，背景只剩从面板缝隙透出一点，
  用户反馈"还是显示不了" → 恢复半透明才对。**图的位置和 veil 的透明度是两件事，
  必须一起改。**

### 顺带修的两处旧版语义偏差

- `backgrounds_dir()` 原来找 exe 旁的 `assets/backgrounds/`。旧版 1.8.2

绝对路径 / 盘符相对(`C:foo`) / 反斜杠分隔，再做一次**词法归一化**确认仍在
base 内（`normalize_lexically`，不能用 `canonicalize`——目标目录还没建）。
配 5 个测试。**顺带注意：sevenz-rust 的 RUSTSEC-2026-0245 就是同一类漏洞。**

**2. 分配 DoS（icons.rs，已修）**
`Vec::with_capacity(e.size())` —— `e.size()` 来自**归档头**（谁做的包谁说了算），
恶意 `icons.zip` 声明 100G 就直接 OOM abort。改成 `read_capped(r, claimed)`：
预分配按 `MAX_ICON_BYTES`(16MB) 封顶，读取用 `.take()` 再兜一层。

**3. quick-xml 0.36 → 0.41（真 CVE，升了）**
RUSTSEC-2026-0194（重复属性检查二次方时间）+ -0195（NsReader 命名空间无界分配）。
API 变了：0.41 **删了 `BytesText::unescape()`**，要用 `decode()`（0.36 那个
`unescape` 才是等价物）。我们没用 `NsReader`，所以 -0195 本来就不适用。
改 2 处：`listxml.rs:436`、`options/mod.rs:428`。27 项测试全过（解析行为未变）。

**4. sevenz-rust RUSTSEC-2026-0245（判定不适用）**
漏洞全在 `de_funcs.rs` 的 `decompress_impl` 及所有 wrapper（自己拼路径写文件）。
